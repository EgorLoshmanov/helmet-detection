# FORTNITEBALLS — пайплайн проекта

Версия: 1.1  
Дата фиксации: 19 сентября 2026 года  
Последнее обновление: 22 сентября 2026 года  
Платформа: Firefly ROC-RK3588S-PC, Rockchip RK3588S  
Задача: обнаружение отсутствия защитной каски в реальном времени с физической сигнализацией

Этот файл является основным рабочим планом проекта. Выполненные пункты отмечаются флажком `[x]`. Существенные изменения модели, классов, оборудования или архитектуры записываются в раздел «Принятые решения».

## 1. Конечный результат

Система должна автоматически выполнять всю цепочку:

```text
Камера
  → получение кадра в реальном времени
  → preprocessing
  → RKNN-модель
  → инференс на NPU RK3588S
  → обнаружение helmet / no_helmet
  → временное подтверждение нарушения
  → включение LED и звукового сигнала
```

Демонстрация считается успешной, если человек без каски вызывает тревогу, надетая каска выключает тревогу, а отсутствие людей в кадре не вызывает ложный сигнал.

## 2. Принятые решения

- Команда: **FORTNITEBALLS**.
- Основная задача: object detection.
- Базовая модель для первого рабочего прототипа: **YOLOv8n**, вход `640 × 640`.
- Классы модели: `helmet` и `no_helmet`.
- Модель обучается или дообучается командой на собственном наборе данных.
- Базовый источник данных: открытый датасет касок и собственные кадры с используемой камеры.
- Финальный инференс выполняется в формате RKNN на NPU RK3588S.
- Firefly находится в университете и используется как удалённый стенд через NetBird и SSH.
- Обучение YOLO, экспорт ONNX и конвертация RKNN выполняются на рабочем компьютере. На Firefly передаются готовая RKNN-модель и приложение инференса.
- Исходный код хранится локально; развёртывание на плату выполняется воспроизводимым скриптом через SSH/SCP или rsync.
- Первая камера для прототипа: USB UVC. MIPI-CSI рассматривается после готовности основной цепочки.
- Периферия подключается поэтапно: консоль → встроенный LED → ESP32 по UART или внешний буззер.
- Прямое питание буззера от GPIO запрещено. Для прямого подключения используется транзистор или MOSFET.
- Если преподаватель потребует модель, отсутствующую в RKNN Model Zoo, YOLOv8n заменяется на YOLO26n. Остальная архитектура проекта сохраняется.
- Экспорт в ONNX/RKNN выполняется после дополнительного цикла сбора целевых кадров и дообучения: базовая модель хорошо работает на исходной валидации, но пока неудовлетворительно переносится на обычную веб-камеру.

### Разделение локальной и удалённой работы

На рабочем компьютере выполняются:

```text
подготовка датасета
обучение YOLO
валидация PyTorch
экспорт и валидация ONNX
конвертация ONNX → RKNN
ведение исходного кода и документации
```

На Firefly выполняются:

```text
захват изображения с физической камеры
RKNN-инференс на NPU
postprocessing
логика SAFE / PENDING / ALARM
управление LED, UART, ESP32 или буззером
измерение производительности
```

Рекомендуемый цикл развёртывания:

```text
локальное изменение кода
  → автоматическая проверка
  → scripts/deploy.sh
  → копирование по SSH
  → запуск на Firefly
  → сохранение логов и метрик обратно в проект
```

## 10. Этап 8 — логика безопасности

Состояния системы:

```text
SAFE     — подтверждённых нарушений нет
PENDING  — no_helmet появился, ожидается подтверждение
ALARM    — нарушение подтверждено
```

- [ ] Пустой кадр без людей считается безопасным.
- [ ] Одиночная ошибочная детекция не включает тревогу.
- [ ] Тревога включается после нескольких подтверждений `no_helmet`.
- [ ] Тревога выключается только после серии безопасных результатов.
- [ ] Порог confidence вынесен в конфигурацию.
- [ ] Задержки включения и выключения вынесены в конфигурацию.
- [ ] Логика проверена для одного и нескольких людей.

Начальные параметры для настройки:

```text
alarm_on_frames:  5–10
alarm_off_frames: 15–30
no_helmet_conf:   около 0.5
```

Критерий завершения: система не дребезжит между состояниями и не включает тревогу в пустом помещении.
